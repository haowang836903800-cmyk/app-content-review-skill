# app内容审核skill

用于豆包App / Peiyao的脚本、图文、视频初审、飞书定位批注和新BF/案例学习。中文显示名为“app内容审核skill”，调用名 `$app-content-review`。GitHub使用ASCII仓库名 `app-content-review-skill`。

先读 [SKILL.md](SKILL.md)。人用文档：

- [我方审核手册](guides/我方审核手册.md)
- [给达人的交稿说明](guides/给达人的交稿说明.md)
- [选号与内容建议](guides/选号与内容建议.md)
- [学习覆盖与限制](学习覆盖清单.md)

**没有问题就通过，不硬挑、不刷批注。** 脚本通过只覆盖脚本；视频完整通过必须实际连续看过并听过原音。历史学习的抽帧和机器转写只支持对应范围的初筛判断。

批注只给白话修稿建议，直接说哪里要改、怎么改。审核依据、复核标准、BF出处链接和审稿编号保留在内部，不显示给达人；视频保留必要的版本和时间点。

## 使用

把本目录安装为 `~/.codex/skills/app-content-review`，保留SKILL.md、references、scripts、guides、agents。需要可用的Python3.9+、lark-cli与用户已授权的飞书访问。视频实际播放/听音、浏览器和媒体处理能力随环境变化，缺失时明确标记。

“用app内容审核skill审核这份脚本，按对应BF在这份飞书稿件内批注：[链接]。”

“复审这个V3，核对上轮意见；没问题就通过，不必再给优化意见。”

“学习这份新BF，包括正文链接，更新相应方向，但保留仍在做的旧方向。”

不用设置问题数量。用户只要求历史学习时，不向历史稿写评论。外部写入工具只负责定位、校验和读回，内容判断由审核过程结合实际证据完成。

## 已实现并验证

文字实际段落定位评论；视频实际附件块定位并带当前时间区间；已解决/未解决评论和回复分页；源文和附件变更校验；本地回执及评论正文与锚点防重；写后读回锚点；零问题不写评论。原线程复审回复可按写回文档执行。

视频批注是附件上的时间点文字，**不是播放器原生时间轴评论**。不会自动改客户表进度、替甲方终审或自动发布内容。不会在学习时执行ADB/清理/补丁等系统改动。

## 验证与维护

`python3 -m unittest discover -s tests -v`。规则校准见 evaluations；当前验证回执见 `验证记录.md`。日更和周更由Codex自动化执行，流程见 references/update-workflow.md，本机配置和原始学习资料在工作目录work/state和work/source，不入库。

仓库保持私有。不会上传原始客户稿、群聊天、视频、图片、凭证或访问参数。所有数据结论按当时快照解释；这不是持续最新的产品事实数据库，使用时仍查对应BF。
