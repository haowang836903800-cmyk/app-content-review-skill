# 视频、图文与改稿复审

## 文件身份先固定

把“稿件文档ID + 附件块ID + token + 文件名 + SHA-256 + 时长 + 送审版本”记在审核单。文档里V1/V2、参考视频、原生结果短片、最终成片可能同时存在；不按文件排列先后猜定稿。当前表格与文档标题不一致时核正文/回复/本次指定版本。

下载成功只代表取得文件。一个文件的SHA相同可复用已有观察，但仍保留它在各稿件中的引用身份；不同SHA即使文件名一样也要重审。视频附件块可带时间段评论，不能冒称播放器原生时间轴评论。

可用 `lark-cli docs +media-download --token 附件token --output work/review/当前源文件.mp4 --as user` 取得授权源文件。`scripts/prepare_media.py --file 本地视频 --out 新目录 --token 实际token --block-id 实际块 --version V3 --audio` 生成原分辨率分布帧、原音WAV及SHA/时长清单。依赖ffmpeg，可用--ffmpeg传路径，--start/--end/--frames用于关键区间加密。清单默认reviewed=false；导出后必须实际打开观察和听音，不能把生成文件当成看过。

## 三种覆盖等级

|覆盖|能判断|不能宣称|
|---|---|---|
|正文/脚本+评论|主线、事实主张、BF匹配、预计镜头与条件|实际成片已做到、发音和剪辑没问题|
|源视频抽帧+ASR|所见帧的入口/产物、字幕、转写线索、明显矛盾|完整连续观看、听过原音、口型/转场/BGM/无残帧通过|
|连续实际播放+原音实听|完整时序、声音、节奏、动作、字幕和细节|功能在所有设备都有效、后续长期执行已经发生|

2026-11-05历史学习采用第二级：355附件token，326唯一SHA，每文件16个分布帧和机器转写；必要处另放大。不是326部全音画看完。未来送审有连续播放/听音工具时先完成第三级；环境不支持时交付已覆盖部分，列出声音/动作缺口，不把转写当耳朵。

## 实际审核顺序

1. 正常速度看一次，确认完整、声音存在、故事及结果能理解；记录真实查看区间和音轨，不先按稿猜画面。
2. 核关键证据：起始条件→入口→输入/授权→执行→打开结果→必要的复用/回执。暂停放大关键信息；聊天“已完成”不替代文件或回执。
3. 对照口播、字幕、贴纸和屏幕：价格/日期/对象/平台、仓库和作者、时间单位、版本名、任务频率、结果数量。
4. 看需要动态观察的动作与细节：鹈鹕脚踏/手部接触、闪卡随角度变化、转场残帧、口型、字幕进出。静态好看不能证明运动正确。
5. 听人声可懂、补录拼接、BGM是否压人声、发音；ASR只是定位帮助。未实听的音频意见禁止写成事实。
6. 全部图文逐页看原图：小字/链接/品牌、原图与生成图对应、结果缺陷、隐私和模板残留。总览缩略图只算概览。
7. 连同封面、发布文案、tag、可复制指令一起复核。不能稿内过了就认为发布页一致。

## 复审不是重提一遍意见

先列旧意见：对应版本/原位置/要求/当前证据/状态（已改、未改、部分改、暂无法核）。重新定位新文件时间点。确认“回退V1”或“以第二张为定稿”等回复，别执着自己的上一版。

修改完成且本轮覆盖充分，可以零新增问题通过。需要回复时在原线程简短指出本版证据；不擅自解决甲方线程、不删除他人意见。旧线程已解决且API不允许回复时，本地报告闭环，必要的新问题另起定位评论。

外链发布视频与稿件附件可能不同：学习时分别记录是否打开实际发布页、是否取得发布版源文件、能否匹配SHA；不能因附件审过就把发布版标为完整看完。
