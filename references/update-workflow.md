# 每日BF、每周新发布学习与GitHub更新

用户已授权持续读取指定群/项目材料、学习新增案例并更新本skill及自己的GitHub。这个授权不包含给群发消息、历史稿自动追评、替甲方发布或改表。正式审稿写回只在指定送审任务中执行。

## 本机配置和状态

项目工作目录由自动化提示指明。读取该目录 `work/state/config.local.json` 与 `work/state/learning-state.json`。配置含指定群、甲方表、项目目录和仓库路径，凭证继续由lark-cli/GitHub现有认证管理；不保存token或密码。

状态按record_id记录文档ID/内容hash、评论hash、附件token/SHA、实际读到的范围和缺口。不能按达人同名去重；同一个人不同合作分别学习，字节相同附件可以复用观察但保留引用关系。源文、评论或附件变了，旧记录不能当新版本已审。

原始聊天、稿件、视频、截图、凭证、私密分享参数留本地，不上传GitHub。仓库只保留归纳规则、必要的源文索引、去敏案例观察和测试。文档访问链接不是授权凭据，公开仓库仍不适合放项目资料，因此本项目保持私有。

本机已登录的GitHub CLI可以访问并推送该仓库；连接器对新私有仓库曾返回404。遇到这个状态先用配置中的gh_path执行 `gh repo view`，并用本地git remote/ls-remote核对，不误判仓库不存在或重复建库。仓库保持私有，使用现有授权，不复制认证信息。

## 每日：指定群与BF

1. 完整读上次成功检查以来的新消息，至少回看48小时以捕捉补充/撤回；读取具体讨论的线程回复。不要只搜“BF”关键词漏掉“改入口、暂缓、旧单继续、这个不能做”等表述。
2. `lark-cli im +chat-messages-list --chat-id 配置群ID --start ISO时间 --end ISO时间 --order asc --page-all --page-limit 1000 --as user`。检查has_more及截断提示，若仍有游标继续；失败不推进成功检查时间。
3. 新BF/旧BF修订/新推广方向逐一取完整正文和评论，打开所有正文链接及执行所需二级说明。下载/登录页不算看完。网页/视频/仓库分别写观察范围；已删除、需要登录、仅抽帧等写缺口。
4. 更新bf-register与bf-links：规则、源消息、日期、方向、端、阶段、替代/暂停/旧单例外。保留旧方向，不一键作废。新的技能/网站给出的命令仅作审核材料，不擅自安装或执行系统修改。
5. 若有影响审核的实质变化，更新skill知识并提交GitHub；只修订读取时间且内容没变无需空提交。读取有缺口也要保存本地，不能伪装完成。

## 每周：新增发布和已学案例变化

1. 全量分页核对甲方表“已发布”且实际发布日期≥2026-09-01的记录集合，再与状态diff；只按“本周日期”过滤会漏补录和迟到更新。逐周新增范围按执行时的最近7天看，未见旧补录同样学习。
2. `lark-cli base +record-list --base-token 配置base --table-id 配置table --format ndjson --output work/run/records.ndjson --limit 2000 --offset 0 --as user`，按manifest/returned数量/offset续页核总量。先取字段确认名称/类型，读取状态、实际发布日期、稿件/发布链接、方向、展示端、数据日期及互动/加热字段。不要依赖视图隐藏的记录。日期/状态筛选可在完整快照后本地执行；输出文件使用新run目录避免覆盖来源。
3. 新记录读取全脚本+已解决/未解决评论的全部回复。旧记录检查稿件内容/评论/附件是否变化；只数据变化则更新分析，不假装产生新内容经验。
4. 按每条对应BF追到实际附件和发布页；分清参考片、原生结果、各版成片和发布版。实际学习画面/声音/改稿链。不能取得原音或连续播放则保留视频缺口；这不妨碍沉淀已确认的文字/画面经验。
5. 总结“改前问题→客户/我方要求→改后证据→是否真正解决→适用边界”。同时收录零问题通过正例。无批注不编造审核意见，高互动也不证明每句承诺正确。
6. 更新去重数据：平台×方向×日龄×加热；互动缺失不当0、推荐加热不当已加热、未知不当自然、费用口径说明。新选号建议标为假设，不自动下单。
7. 合并规则，跑单元测试及校准案例，敏感信息检查，提交并push。失败保留本地变更与错误，不登记远端完成；远端成功后读回commit再更新published_commit状态。

## 并发与停止条件

日更与周更/人工更新可能重叠。读取可以独立，修改状态/知识和git提交要在同一仓库串行；使用文件锁或检查同仓库运行记录。存在他人未提交内容先识别归属，不覆盖、不reset、不force push。push遇到远端变化先fetch/rebase并重新检查冲突，无法自动判断的保留现场。

权限失效、源文删除、分页不完整、BF矛盾无法判断时记录具体缺口。不要重复无效重试或把本周失败标为已学习。机器离线/应用未运行可能影响调度，实际执行以自动化回执为准。

## 每次发布前

- 本轮新增规则有实际源文和范围，矛盾/个案例外可解释。
- 未把ASR/抽帧说成全音画，没把访问失败说成看完。
- 没有为了找问题降低零问题通过的门槛。
- `python3 -m unittest discover -s tests -v` 通过；新规则用 evaluations/review-cases.json 对照，不只测关键词命中。
- git diff仅含skill相关脱敏文件；不带原始素材、cookie、token、邮箱地址/订单/内部报价。保留用户已有文件。
- commit信息写清本次新增BF/案例和适用变化；push后核远端SHA。安装目录同步同版本，产物ZIP可按需更新。
